# 공통 화면 기획 (5차 시안 기준)

- 작성일: 2026-10-13
- 상태: SHY 확인 대기 (남은 확인 사항은 맨 아래)
- 시안 페이지: [common-screens-mockup.html](./common-screens-mockup.html) (GitHub Pages가 켜져 있으면 `https://okeycsy.github.io/connect-link/docs/design/common-screens-mockup.html` 에서 열림)
- 요구사항 원본: Notion "요구사항/기능 명세"

이 문서는 네 업무 영역(계좌통합관리, 자동이체통합관리, 대출이동, CMS)이 함께 쓰는 공통 화면의 구조와 디자인 언어를 정리한 것이다. 목업의 기관·사람·번호는 모두 가짜 데이터다.

| '전체' 레일 | 운영·상황실·대외계처럼 전 업무를 보는 결제원 직원에게만 표시 | 확인 대기 |

### 결정 이력

1. 1차 (2026-10-13): A 워크벤치 / B 할 일 홈 / C 업무 워크스페이스 세 안 비교. SHY 선택: C 구조 + B 홈 + A 스타일, CI 색, 단일 로그인.
2. 2차: CI 파랑 적용. SHY가 CI 색 제외를 요청, 레퍼런스 팔레트 3종(잉크·인디고·딥 틸) 제시.
3. 3차: SHY 지시로 비비드 블루 + C안 레일·보조 메뉴 복귀, A 스타일 제외. 이어서 남색 제거, 채도 낮춘 블루를 배경 메인색으로.
4. 4차: "너무 단조롭다, 상장 앞둔 소프트웨어 회사 기준으로" 요청. 네 방향(프리미엄 핀테크, 제품 주도 SaaS, 한국 소비자용, 엔터프라이즈 데이터)을 만들어 비교한 뒤 핀테크 톤을 뼈대로 합쳐 네 겹의 깊이(레이어드 블루)로 정리.
5. 5차: SHY 지시로 메인색을 남색으로 바꾸고 색 수를 최소로. 네 겹의 깊이는 그대로 두고 팔레트만 남색 + 빨강 하나로 줄여 레이어드 네이비로 정리.

## 3. 디자인 언어: 레이어드 네이비 (대체됨)

> 2026-10-15 SHY 결정으로 디자인 언어는 **B안 메신저형**으로 바뀌었다. 색·글꼴·radius·셸 치수·컴포넌트 규칙은 [`frontend/CLAUDE.md`](../../frontend/CLAUDE.md)가 기준이고, 이 절은 이력으로만 남긴다. 1·2절의 화면 범위와 구조 결정(레일 + 보조 메뉴, 홈 카드 대시보드, 목록 + 오른쪽 패널)은 그대로 유효하다. 2절 표의 메인색·색 수 결정도 B안으로 대체되었다.

남색 하나를 네 겹으로 쌓는다. 유채색은 남색과 그 틴트, 그리고 급한 것에만 쓰는 빨강 하나뿐이다. 상태와 진행률은 남색의 밝기 차이로 읽고, 숫자는 전용 서체로 한글 본문과 질감을 나눈다.

### 깊이 4층

| 층 | 요소 | 레시피 |
| --- | --- | --- |
| 0 크롬 | 상단 바, 레일, 로그인 패널, 홈 밴드 | `linear-gradient(180deg, #1B2F58, #0F1E3C 55%, #0B1730)` + 좌상단 radial 글로우(rgba(90,125,205,.42), 55%) + SVG feTurbulence 그레인(알파 .07). 레일은 어두운 스크림으로 한 단계 깊게 |
| 1 프로스트·시트 | 보조 메뉴, 본문 영역 | 보조 메뉴 rgba(255,255,255,.88) + blur 12px. 본문은 #F2F4F8 시트가 radius 14로 크롬 안에 끼워짐 |
| 2 카드 | 카드, 폼, 표 본문 | #FFFFFF, 1px #D9DEE8, radius 12, 그림자 `0 1px 2px rgba(27,42,74,.06), 0 12px 28px -18px rgba(15,30,60,.28)`. 흰색은 여기에만 |

크롬 위에 올라가는 그래픽(진행 헤어라인, 스파크라인, 연결 그래프의 강조 선)은 흰색이다. 정상 상태에 따로 초록을 쓰지 않고, 확인됨 점은 남색, 비활성 점은 navy-300이다.

### 시그니처 요소

1. 남색 위의 시트: 본문이 radius 14의 시트처럼 크롬 안에 끼워져 모서리 밖으로 그라데이션이 비친다.
2. 글래스 KPI 타일: 홈 첫 줄, 남색 밴드 위 반투명 타일 네 개. 숫자 전용 서체, 흰 진행 헤어라인 또는 흰 스파크라인.
3. 빨강은 하나, 두 단계: 마감 임박은 흰 배경에 빨간 테두리, 초과·미확인·새 알림은 빨간 채움. 그 밖에는 쓰지 않아서 어디서든 '급한 것'으로 읽힌다.
4. 링 게이지와 업무별 스택 바: 정기 변경 진행률은 링, 업무별 완료 수는 남색 네 단계(#0F1E3C, #3A4F7A, #6F80A6, #A9B4CC)로 쌓은 바.
5. 레일 토큰과 기관 모노그램: 업무는 둥근 사각 토큰, 기관은 두 글자 모노그램 타일(navy-100 바탕에 남색 글자). 레일, 표, 상세 패널에 반복.
6. 키캡과 헤일로 점: Ctrl K 키캡, 상태 점은 8px 점 + 연한 외곽 링.

### 글꼴, 아이콘, 모션

- 본문·UI: Pretendard Variable (OFL, npm `pretendard` 번들). 숫자·라틴: Geist (OFL). 식별자·키캡: Geist Mono. 스택을 `Geist, Pretendard Variable`로 두면 숫자만 Geist로 떨어진다. (Geist 도입 여부는 확인 대기)
- 크기 11 / 12 / 13 / 14 / 16 / 20 / 24 / 32px. 한글 `word-break: keep-all`, 숫자 `font-variant-numeric: tabular-nums`.
- 아이콘: Tabler Icons (Mantine 기본 짝, 번들).
- 모션: 160~240ms, `cubic-bezier(.2,.8,.2,1)`, 튕김 없음. 레일 토큰 180ms 슬라이드, 보조 메뉴 200ms 크로스페이드, 링 게이지 첫 로딩 1회 600ms, 상세 패널 240ms. `prefers-reduced-motion`에서는 투명도 전환만.
- 런타임에 CDN이나 외부 폰트를 쓰지 않는다. 시안 HTML만 Google Fonts를 대신 썼다.

## 5. 함께 검토했던 다른 방향 (4차, 참고용)

| 방향 | 요지 | 참고 |
| --- | --- | --- |
| 루미너스 레일 | 크롬을 빛을 받은 패널로. 1px 하이라이트, 글래스 보조 메뉴, 키캡 커맨드 팔레트, 기관 모노그램 | Linear, Vercel, Figma, Raycast |

## 6. 남은 확인 사항

1. '전체' 레일을 전 업무 담당 결제원 직원에게만 보이게 하는 것이 맞는지.
