# 명세에 없던 결정

명세(Notion "요구사항/기능 명세")와 CLAUDE.md 가 정하지 않은 것을 작업 중에 정한 기록. 한 줄에 날짜, 결정, 이유. 같은 질문이 다시 나오면 여기부터 본다.

| 날짜 | 결정 | 이유 |
| --- | --- | --- |
| 2026-10-15 | Java 17 호환은 Gradle 툴체인 대신 `options.release = 17` 로 보장한다. 빌드 JDK 는 17 이상 아무거나. | 툴체인 자동 내려받기(foojay)가 막힌 환경이 있다. `--release 17` 이면 JDK 21 로 빌드해도 17 에 없는 API 를 쓰면 컴파일이 실패한다. CI 는 JDK 17 로 돈다. |
| 2026-10-15 | 본문 글꼴은 Pretendard Variable 을 npm 패키지로 번들한다. CLAUDE.md §7 의 "시스템 폰트" 는 이 결정으로 대체. | 확정된 화면 기획(docs/design/common-screens.md)이 Pretendard 를 정했다. OFL 이고 빌드 결과에 포함되므로 외부 호출이 없다. 숫자 서체 Geist 는 SHY 확인 전까지 넣지 않는다. |
| 2026-10-15 | 화면 구조는 CLAUDE.md §7 의 "왼쪽 메뉴 하나" 대신 화면 기획의 레일(업무 영역) + 보조 메뉴(기능) 2단이다. 주소는 `/{업무 slug}/{기능}`. | docs/service-taxonomy.md 와 화면 기획이 뒤에 확정됐다. |
| 2026-10-15 | 업무 영역은 테이블이 아니라 `Business` enum 이다. API `/api/v1/businesses` 가 slug·이름을 내려 주고 화면은 그것을 쓴다. | 네 가지로 고정된 프로토타입 범위이며 권한·주소에서 코드로 참조한다. 세부업무는 자유 텍스트. |
| 2026-10-15 | OpenAPI 문서는 서버 테스트(`OpenApiExportTest`)가 `backend/build/openapi.json` 으로 내보내고, `gen:api` 는 그 파일을 읽는다. | 서버를 띄우지 않고도 타입을 만들 수 있고 CI 에서 결정적으로 검사된다. |
| 2026-10-15 | "외부 URL 없음" CI 검사는 `dist/index.html` 의 `src/href` 와 CSS 의 `url(http…)` 만 본다. | JS 번들 안의 URL 문자열(라이브러리 오류 메시지 링크 등)은 실제 호출이 아니라 잡지 않는다. |
| 2026-10-15 | `/api/v1/organizations`, `/api/v1/businesses` 는 로그인 없이 연다. 이름·구분·코드만 내려 준다. | 회원가입 화면(로그인 전)이 기관과 업무 선택지를 써야 한다. 연락처 같은 민감 정보는 담지 않는다. |
| 2026-10-15 | 샘플 기관 코드는 짧은 대문자(`GANA`, `DARA`…)이고 이메일 도메인은 `*.example.com`. | 공개 저장소 규칙. 도메인은 가입 승인 화면의 "이메일 도메인과 기관 일치 여부" 에 쓴다. |
| 2026-10-15 | '전체' 레일(전 업무 조회 결제원 직원용)은 아직 넣지 않는다. | 화면 기획의 확인 대기 항목. 계정·권한이 붙은 뒤 SHY 확인을 받아 넣는다. |
| 2026-10-15 | 외부 미리보기는 Render 무료 웹 서비스(Docker)에 올린다. `render.yaml` + `Dockerfile`, `server.port=${PORT:8080}`. SHY 선택. | 여러 기기에서 로컬 빌드 없이 보려면 app.jar 를 실행해 줄 곳이 필요하다. Pages 는 서버가 없어 안 되고, Render 는 main 머지마다 자동 배포된다. 공개 저장소의 가상 데이터만 올라간다. 내부망 시연은 여전히 app.jar 다. |
| 2026-10-15 | 공통 화면(홈~관리)을 계정 모듈보다 먼저, 어드민 전제로 만든다. local·demo 프로필은 `DemoAuthenticationFilter` 가 로그인 없는 요청을 데모 관리자(`admin@kftc.example.com`)로 인증하고, 운영 프로필에는 이 필터가 없어 로그인 API 전까지 보호된 API 가 401 이다. SHY 결정. | 공통 화면이 전부 로그인 사용자에 의존하므로 임시 사용자가 필요하다. 권한 판단은 그래도 Service 의 `XxxAccessPolicy` 에 두어 계정 모듈이 붙으면 사용자만 바뀐다. |
| 2026-10-15 | 알림 받는 사람의 키는 회사 이메일(`recipient_email`)이다. 계정 테이블이 생겨도 이메일로 잇는다. | 명세의 로그인 주체가 회사 이메일이고, 계정이 아직 없는 담당자에게도 메일을 보낼 수 있어야 한다. |
| 2026-10-15 | 발송함(`notification_outbox`)은 outbox 패턴이다. 상태는 `PENDING`/`SENT`/`FAILED` 이고 프로토타입은 `PENDING` 으로만 남긴다. 매터모스트 대상은 알림 대상 설정이 생기기 전까지 이메일 앞부분을 `@handle` 로 쓴다. | 운영에서는 발송기만 바꾸면 되는 구조를 유지하면서 데모에서는 화면으로 확인한다. |
| 2026-10-15 | 알림 센터와 데모 도구 화면은 업무 영역 아래 주소(`/{업무}/notifications`, `/{업무}/demo/outbox`)에 둔다. | 전역 화면이지만 레일·보조 메뉴 문맥을 잃지 않게 하고 라우터 구조를 하나로 유지한다. |
| 2026-10-15 | 홈 "지금 할 일" 은 `home` 모듈이 조립한다. 카드 자리는 `HomeCardKey` 여섯 개(연락처 확인, 정기 변경, 의견 회신, 기관 테스트, 일시중단, 가입 승인)이고, 기능 모듈은 `HomeCardContributor` 빈 하나로 자기 자리를 채운다. 기여자가 없는 자리는 `UNAVAILABLE`("연결 예정") 카드다. | 홈은 기능별 카드가 모이는 화면이라 계약 한곳에 두고, 화면은 카드 모양(요약·숫자·진행률·항목)만 안다. |
| 2026-10-15 | 기능 프로젝트가 붙기 전까지 네 기능 카드와 가입 승인 카드는 `home/sample` 의 샘플 기여자(local·demo·test 프로필)가 채운다. 테이블 대신 Java 상수이며 `SAMPLE` 출처로 표시된다. SHY 선택("샘플로 채우기"). | 화면을 완성해 보여 주되 Flyway 마이그레이션 빚을 남기지 않는다. 실제 기여자가 생기면 그 자리의 샘플 클래스만 지운다. |
