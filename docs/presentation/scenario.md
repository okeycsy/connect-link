## 1. 과제 (가상)

**자동이체 해지 결과 배치파일 개선**

- **배경**: 고객이 자동이체통합관리에서 자동이체 해지를 신청하면 결제원이 기관에 해지 요청 파일을 보내고 기관이 처리결과 파일을 돌려준다.
  지금은 처리결과가 **다음 영업일에 하루 한 번** 오고, 해지가 안 됐을 때 사유가 **"처리 불가" 하나뿐**이다.
  고객은 결과를 늦게 알고 왜 안 됐는지 몰라 민원이 생긴다.
- **개선안**
  1. 처리결과 파일 회신을 **당일 2회(13시·18시)** 로 늘린다.
  2. 결과 파일에 **불가 사유코드**를 더한다(미납 잔액 있음, 기관에서 직접 해지 필요, 출금계좌 해지됨).
- **등장인물(데모 계정, 비밀번호 `demo1234!`)**
  - 결제원 업무·개발 담당: **문서준 과장**(`moon.seojun@kftc.example.com`, 자동이체통합관리 현업)
  - 결제원 운영 담당: **김태호 대리**(`kim.ops@kftc.example.com`, 전 업무 운영)
  - 참가기관 담당: **신한은행 이준호 과장**(`lee.junho@shinhan.example.com`, 전산 개발·대외계)
  - 그 밖의 대상 기관: KB국민은행, 우체국, 저축은행중앙회, 삼성증권, 신협(자동이체통합관리 참여 기관 6곳)

## 3. 장별 대본과 영상 장면

### ⓪ 준비 — 담당자부터 찾는다 (`prep`)

- **as-is(장표, 말)**: "과제를 시작하려면 먼저 기관 담당자에게 연락해야 합니다. 작년 엑셀 명부로 메일을 보냈더니 세 통이 반송됐습니다. 담당자가 바뀐 걸 그제야 압니다."
- **영상**
  1. 문서준(결제원)으로 로그인 → 연락처(자동이체통합관리). 6개 기관의 세부업무별 담당자와 **최근 확인일**을 비춘다.
     - 말풍선: "기관이 직접 현행화한 **최신 명부**. 6개월이 지나면 기관에 다시 확인을 묻습니다."
  2. 한 기관을 눌러 상세 패널 → 변경 이력(이전 담당자, 휴대폰은 가려서)을 짧게.
  3. "정기 변경 주간" 버튼을 짧게 비춘다(반기마다 자동 요청·미완료 기관만 리마인드).

### ① 업무팀 — 회의, 의견조사, 요건 확정 (`biz`)

- **as-is(말)**: "회의 안내 메일을 보내고, 참석 여부 회신을 하나하나 셉니다. 회의 뒤 의견조사도 메일로 받아, 기관마다 다른 양식을 열어 취합표에 옮깁니다."
- **영상**
  1. 문서준: 공지·자료실의 "자동이체 해지 결과 배치파일 개선 실무 회의 개최 안내"(참석 회신 요청을 이어 둔 글)를 비춘다.
  2. 이준호(신한은행)로 전환: 공지에서 **[회신하기]** → 참석 · 참석자 입력 → 최종제출.
  3. 문서준: 참석 회신의 **회신 현황**이 바로 늘어난 것을 비춘다. 미회신 기관만 리마인드(메일 미리보기).
  4. 카드: "회의를 마쳤습니다. 이제 기관별 의견을 묻습니다."
  5. 문서준: 의견조사 "해지 결과 배치파일 개선 의견조사"의 질문을 비춘다(섹션·답별 이동). 대상은 연락처에서 세부업무로 골라 담는다.
     - 질문 1(객관식, 필수): 처리결과 파일을 당일 2회(13시·18시) 회신할 수 있습니까? 가능 → 섹션 2 / 어려움 → 섹션 3
     - 섹션 2 "적용 계획": 적용 가능한 시기(객관식: 1분기 / 2분기 / 하반기)
     - 섹션 3 "어려운 이유": 어려운 이유와 대안(주관식)
     - 섹션 4 "공통": 추가 개발이 필요한 사유코드(체크박스: 미납 잔액 있음 / 기관에서 직접 해지 필요 / 출금계좌 해지됨), 개발 소요 기간(주관식)
  6. 이준호: 질문 1 "가능" → 적용 시기 질문이 나타남 → "어려움"으로 바꾸면 이유 질문으로 바뀌는 것을 보여 주고 다시 "가능" → 답 → 최종제출.
  7. 문서준: **취합표**(기관별 답, 건너뜀 표시)와 질문별 집계 → [엑셀 다운로드](업무망) 버튼 비추기.
  8. 카드: "요건 확정 — 당일 2회(13·18시) 회신 · 불가 사유코드 3종 · 2분기 시행"

### ② 개발팀 — 개발 요청, 테스트데이터, 실시간 현황 (`dev`)

- **as-is(말)**: "개발 요청 메일을 보내고, 테스트데이터와 결과를 메일로 모아 매일 17시 기준 현황표를 돌립니다. 공유하는 순간 지난 정보라, '어제 테스트했는데 왜 X죠?' 하는 전화가 옵니다."
- **영상**
  1. 문서준: 기관 테스트 "자동이체 해지 결과 배치파일 개선". 요구사항 5개(001 신규 레이아웃 파일 수신, 002 13시 1차 회신, 003 18시 2차 회신, 004 사유코드별 처리, 005 오류 파일 재송신), 대상 기관 6곳, 세부업무별 테스트 담당자.
     **테스트데이터 사전 요청** 카드(생성 완료 n/6) → [미생성 기관에 다시 요청].
  2. 이준호: 자기 기관 테스트 화면 → 테스트데이터 "생성 완료" 저장 → 요구사항 결과 등록(002 정상, 003 오류 + 특이사항) → [결과 저장].
  3. 문서준: 기관별 현황에서 **신한은행 수행률이 바로 바뀐 것** → 신한은행 행을 열어 003 결과에 결제원 의견(미니 수행률·특이사항).
  4. 이준호: 자기 기관 수행률과 결제원 의견을 **같은 화면에서 실시간으로** 확인 → 답글.
     - 말풍선: "기준 시각 현황표가 없습니다. 양쪽이 같은 화면을 봅니다."

### ③ 운영팀 — 시행 첫날 모니터링, 장애 대응 (`ops`)

- **as-is(말)**: "시행 첫날, 13시 파일이 안 들어온 기관이 있습니다. 지금은 명부를 뒤져 기관마다 전화합니다. 누가 확인했는지도 따로 적어 둡니다."
- **영상**
  1. 김태호(운영): 소통 채널 → 자동이체통합관리 단체방 → "@신한은행 13시 해지 결과 파일이 아직 들어오지 않았습니다. 확인 부탁드립니다." 전송.
  2. 이준호: 방 목록의 **@ 표시** → 메시지 **[확인]** → "13시 20분에 재송신했습니다." 답장.
  3. 김태호: 메시지 아래 "신한은행 확인"이 남은 것 비추기.

### ④ 며칠 뒤 — 일시중단 (`susp`)

- **as-is(말)**: "며칠 뒤 신한은행에서 전산 작업 공문이 옵니다. 업무명이 '대고객 서비스 전체'라, 대고객 채널만 멈추는지 우리 원과의 연계까지 멈추는지 다시 물어야 합니다."
- **영상**
  1. 카드: "며칠 뒤"
  2. 이준호: 일시중단 등록 → 대상 업무에서 **자동이체통합관리 · 납부자자동이체**를 직접 고름 → 일시·이유 → 공문 첨부 → 저장(검토 대기).
  3. 데모 발송함에서 "매터모스트" 알림 줄 비추기(관련 업무 담당자에게 바로 알림).
  4. 김태호: 검토 대기 건 → [확인 시작] → [조치 쓰고 확정] → 확정. 확정 건은 운영·관제 매터모스트 채널로 가고, 정해진 때마다 자동으로 모아 보낸다.

## 5. 발표 때 확인할 것

- 숫자: 업무 1개 연 약 198시간, 94개 업무 연 1만 8,612시간(1차·소개자료와 같다).
