## 1. 과제 (가상)

**자동이체 해지 결과 배치파일 개선**

- **배경**: 고객이 자동이체통합관리에서 자동이체 해지를 신청하면 결제원이 기관에 해지 요청 파일을 보내고 기관이 처리결과 파일을 돌려준다.
  지금은 처리결과가 **다음 영업일에 하루 한 번** 오고, 해지가 안 됐을 때 사유가 **"처리 불가" 하나뿐**이다.
  고객은 결과를 늦게 알고 왜 안 됐는지 몰라 민원이 생긴다.
- **개선안**
  1. 처리결과 파일 회신을 **당일 2회(13시·18시)** 로 늘린다.
  2. 결과 파일에 **불가 사유코드**를 더한다(미납 잔액 있음, 기관에서 직접 해지 필요, 출금계좌 해지됨).
- **등장인물(데모 계정, 비밀번호 `demo1234!`)**
  - 결제원 업무·개발 담당: **문서준 과장**(`moon.seojun@kftc.example.com`, 자동이체통합관리 업무팀)
  - 결제원 운영 담당: **김태호 대리**(`kim.ops@kftc.example.com`, 전 업무 운영)
  - 참가기관 담당: **신한은행 이준호 과장**(`lee.junho@shinhan.example.com`, 전산 개발·네트워크팀)
  - 그 밖의 대상 기관: KB국민은행, 우체국, 저축은행중앙회, 삼성증권, 신협(자동이체통합관리 참여 기관 6곳)

## 3. 장별 대본과 영상 장면

### ⓪ 준비 — 담당자부터 찾는다 (`prep`)

- **as-is(말, 한 문장)**: "먼저 기관 담당자에게 연락해야 합니다. 그런데 팀마다 따로 관리하는 명부로 메일을 보냈더니 세 통이 반송됩니다." (나머지 불편은 장표 왼쪽 글로 둔다)
- **영상**
  1. 문서준(결제원)으로 로그인 → 연락처(자동이체통합관리). 6개 기관의 세부업무별 담당자와 **최근 확인일**을 비춘다.
     - 말풍선: "기관이 직접 현행화한 **최신 명부**. 6개월이 지나면 기관에 다시 확인을 묻습니다."
  2. 한 기관을 눌러 상세 패널 → 변경 이력(이전 담당자, 휴대폰은 가려서)을 짧게.
  3. "정기 변경 주간" 버튼을 짧게 비춘다(반기마다 자동 요청·미완료 기관만 리마인드).

### ① 업무팀 — 회의, 의견조사, 요건 확정 (`biz`)

- **as-is(말, 한 문장)**: "업무팀은 회의를 열고 의견을 묻습니다. 지금은 회신을 독촉하고, 받은 회신을 하나하나 옮겨 취합표를 만듭니다."
- **영상**
  1. 문서준: 공지·자료실의 "자동이체 해지 결과 배치파일 개선 실무 회의 개최 안내"(참석 회신 요청을 이어 둔 글)를 비춘다.
  2. 이준호(신한은행)로 전환: 공지에서 **[회신하기]** → 참석 · 참석자 입력 → 최종제출.
  3. 문서준: 참석 회신의 **회신 현황**이 바로 늘어난 것을 비춘다. 미회신 기관만 리마인드(메일 미리보기).
  4. 카드: "회의를 마쳤습니다. 이제 기관별 의견을 묻습니다."
  5. 문서준: 의견조사 "해지 결과 배치파일 개선 의견조사"의 질문을 비춘다(섹션·답별 이동). 대상은 연락처에서 세부업무로 골라 담는다.
     - 질문 1(객관식, 필수): 처리결과 파일을 당일 2회(13시·18시) 회신할 수 있습니까? 가능 → 섹션 2 / 어려움 → 섹션 3
     - 섹션 2 "적용 계획": 적용 가능한 시기(객관식: 1분기 / 2분기 / 하반기)
     - 섹션 3 "어려운 이유": 어려운 이유와 대안(주관식)
     - 섹션 4 "공통": 추가 개발이 필요한 사유코드(체크박스: 미납 잔액 있음 / 기관에서 직접 해지 필요 / 출금계좌 해지됨), 개발 소요 기간(주관식)
  6. 이준호: 질문 1 "가능" → 적용 시기 질문이 나타남 → "어려움"으로 바꾸면 이유 질문으로 바뀌는 것을 보여 주고 다시 "가능" → 답 → 최종제출.
  7. 문서준: **취합표**(기관별 답, 건너뜀 표시)와 질문별 집계 → [엑셀 다운로드](내부망) 버튼 비추기.
  8. 카드: "요건 확정 — 당일 2회(13·18시) 회신 · 불가 사유코드 3종 · 2분기 시행"

### ② 개발팀 — 개발 요청, 테스트데이터, 실시간 현황 (`dev`)

- **as-is(말, 한 문장)**: "요건이 확정되면 개발과 테스트를 요청합니다. 지금은 17시 기준 현황표를 메일로 돌리다 보니 '어제 테스트했는데 왜 X죠?' 하는 전화가 옵니다."
- **영상**
  1. 문서준: 기관 테스트 "자동이체 해지 결과 배치파일 개선". 요구사항 5개(001 신규 레이아웃 파일 수신, 002 13시 1차 회신, 003 18시 2차 회신, 004 사유코드별 처리, 005 오류 파일 재송신), 대상 기관 6곳, 세부업무별 테스트 담당자.
     **테스트데이터 사전 요청** 카드(생성 완료 n/6) → [미생성 기관에 다시 요청].
  2. 이준호: 자기 기관 테스트 화면 → 테스트데이터 "생성 완료" 저장 → 요구사항 결과 등록(002 정상, 003 오류 + 특이사항) → [결과 저장].
  3. 문서준: 기관별 현황에서 **신한은행 수행률이 바로 바뀐 것** → 신한은행 행을 열어 003 결과에 결제원 의견(미니 수행률·특이사항).
  4. 이준호: 자기 기관 수행률과 결제원 의견을 **같은 화면에서 실시간으로** 확인 → 답글.
     - 말풍선: "기준 시각 현황표가 없습니다. 양쪽이 같은 화면을 봅니다."

### ③ 운영팀 — 시행 첫날 모니터링, 작업 지연 안내 (`ops`)

- **as-is(말, 한 문장)**: "시행 첫날, 해지 요청 파일이 늦게 나갑니다. 지금은 여러 은행에서 한꺼번에 오는 전화에 같은 설명을 되풀이합니다."
- **영상**
  1. 김태호(운영): 소통 채널 → 자동이체통합관리 단체방 → "[지연 안내] 타 기관 수신 지연으로 오늘 해지 요청 파일이 30분가량 늦게 나갑니다. 13시 처리결과 회신은 13시 30분 이후에 부탁드립니다." 전송.
  2. 이준호(신한은행): 방 목록의 읽지 않음 표시 → 메시지 **[확인]**.
  3. 김태호: 메시지 아래 기관별 확인(KB국민은행 · 우체국 · 신한은행 …)이 쌓인 것을 비춘다.
     - 말풍선: "전화 대신 한 번 공지로, 어느 기관이 확인했는지 한눈에."

### ④ 며칠 뒤 — 일시중단 (`susp`)

- **as-is(말, 한 문장)**: "며칠 뒤 '자동이체 서비스 중단' 공문이 옵니다. 페이인포 계좌이동인지, 지로 납부자자동이체인지 다시 물어야 합니다."
- **영상**
  1. 카드: "며칠 뒤"
  2. 이준호: 일시중단 등록 → 대상 업무에서 **계좌이동**(관련 업무 자동이체통합관리)을 직접 고름 → 일시·이유 → 공문 첨부 → 저장(검토 대기).
  3. 데모 발송함에서 "매터모스트" 알림 줄 비추기(관련 업무 담당자에게 바로 알림).
  4. 김태호: 검토 대기 건 → [확인 시작] → [조치 쓰고 확정] → 확정. 확정 건은 운영·관제 매터모스트 채널로 가고, 정해진 때마다 자동으로 모아 보낸다.

### 만든 방식 — 업무 · 개발 · 운영 세 관점을 Claude Code로 (9장)

- 과제 이야기와 같은 세 관점(업무 · 개발 · 운영)을 모두 담아 만들었다는 점으로 잇는다. 팀원이 그 업무의 실제 담당자는 아니므로 "담당자"라고 하지 않고 "세 관점"이라고 한다. 도구 이름은 AI 대신 Claude Code 라고 쓴다.
- 장표 틀은 기대효과 장과 같다(왼쪽 큰 숫자, 오른쪽 표와 카드 3개).
- **말**: "이 연결이는 업무, 개발, 운영 세 관점을 모두 담아, Claude Code에 말로 요청해 6주 만에 만들었습니다. 먼저 내부망 서버 사양과 외부 접속 금지 같은 규칙을 한 장으로 정해 두어, 누가 요청하든 같은 규칙으로 만들어졌습니다. 그래서 파일 하나로 내부망에 올릴 수 있고, 규칙과 결정 기록, 자동 테스트가 남아 있어 담당자가 바뀌어도 이어서 고칠 수 있습니다."
- 숫자(2026-11-22 저장소 기준): 2026-10-11 ~ 11-21 약 6주, 변경(PR) 78건, 코드 약 5만 7천 줄, 서버 테스트 약 470개 + 화면 시나리오 70여 개, 결정 기록 208건(`docs/decisions.md`), 규칙 문서 `CLAUDE.md`.
- "사내 AI 로도 이어서"는 앞으로 할 수 있게 해 둔 것이지 해 본 것은 아니다. 질문이 오면 그렇게 답한다.

### 확산 — 참가기관도 참여할 이유가 충분합니다 (11장)

- 장표에는 참여할 이유만 짧게 둔다(카드 3개: 기관이 얻는 것 / 낮은 문턱 / 단계적 전환, 그리고 확산 순서). 예상 질문은 장표에 적지 않는다.
- **말**: "참가기관도 참여할 이유가 충분합니다. 기관도 우리 원 담당자를 바로 찾고, 자기 테스트 현황을 실시간으로 봅니다. 설치 없이 회사 이메일로 가입하고, 기존 명부는 우리 원이 한 번에 올려 둡니다. 네 개 업무부터 차례로 넓히겠습니다."
- **질문이 오면("참가기관이 안 쓰면?")**: 회신 · 테스트 결과 · 공문은 지금도 기관이 우리 원에 내는 것이고 바뀌는 것은 내는 곳 하나다. 우리 원이 접수 창구를 연결이로 안내하면 된다. 쓸수록 우리 원은 취합이, 기관은 전화와 메일이 줄어든다.
