# 서비스 최상위 분류

- 작성일: 2026-10-15
- 상태: 세부 프로젝트 구성(기능별) 확정, 나머지는 6절 확인 대기
- 원본: Notion "SHY 프로젝트 > 서비스 최상위 분류 (초안)"
- 근거: Notion "요구사항/기능 명세"와 댓글, [공통 화면 기획](./design/common-screens.md)

## 1. 두 개의 축

연결고리는 두 축으로 나뉜다. 왼쪽 레일은 **업무 영역**(어느 업무의 데이터를 보는가), 보조 메뉴는 **기능**(무엇을 하는가)을 고른다. 기능 메뉴는 모든 업무 영역에서 같은 구성으로 반복되고, 업무 영역은 조회·수정 범위를 정한다.

```text
연결고리
├─ [전역] 상단 바 ─────────── 공통
│   ├─ 로그인 · 회원가입 · 승인 대기
│   ├─ 전역 검색 (Ctrl K)
│   ├─ 알림 센터
│   └─ 내 정보 (연락처 확인 · 탈퇴)
│
├─ [축 A] 업무 영역 = 왼쪽 레일
│   ├─ 전체 (전 업무를 보는 결제원 운영·상황실·대외계만, 확인 대기)
│   ├─ 계좌통합관리
│   ├─ 자동이체통합관리
│   ├─ 대출이동
│   └─ CMS
│
└─ [축 B] 기능 = 보조 메뉴 (업무 영역마다 같은 구성)
    ├─ 홈 (지금 할 일) ────────── 공통
    ├─ 가. 연락처 ─────────────── 연락처 프로젝트
    ├─ 나. 의견 요청 ───────────── 의견 프로젝트
    ├─ 다. 기관 테스트 ─────────── 테스트 프로젝트
    ├─ 라. 일시중단 ───────────── 일시중단 프로젝트
    └─ 관리 (권한자만) ─────────── 공통 + 각 기능 프로젝트
```

## 2. 최상위 항목과 담당 프로젝트

세부 프로젝트는 공통 1개 + 기능별 4개다(SHY 확정, 2026-10-15). 각 기능 프로젝트가 네 업무 영역 전체를 맡는다.

| 코드 | 최상위 항목 | 담는 것 | 담당 프로젝트 |
| --- | --- | --- | --- |
| CMN | 공통 (계정·셸·기준정보) | 로그인, 4단계 회원가입, 가입 승인, 앱 셸, 홈 대시보드 틀, 내 정보, 알림 센터, 기관·업무·사용자 기준정보, 권한·조회 범위, 알림 발송(메일·Mattermost) 공통 모듈, 첨부파일, 변경 이력 | 공통 |
| CNT | 가. 연락처 | 담당자 조회·수정·삭제, 최근 확인일과 6개월 확인 알림, 변경 전·후 이력, 정기 변경 주간과 진행률, 후임자 지정 후 탈퇴 규칙, 검색·필터, 엑셀 다운로드(내부망) | 연락처 |
| OPN | 나. 의견 요청 | 요청 작성·수정·취소, 대상 기관·회신 담당자 선택(연락처 연동), 질문(객관식·체크박스·주관식), 기관 회신(임시저장·제출·수정 요청), 회신율·질문별 답 집계, 미회신 리마인드, 취합표·엑셀 | 의견 |
| TST | 다. 기관 테스트 | 개발 건별 테스트 페이지, 요구사항별 결과(정상·오류·수행중·미수행)와 특이사항, 결제원 피드백(미니 수행률), 수행률 집계, 수행 완료 판정, Mattermost 알림 대상 설정 | 테스트 |
| OUT | 라. 일시중단 | 등록(정해진 양식), 상태(검토 대기·검토 중·확정·완료), 조치·인수인계, 현재·예정·지난 조회, 기관별 이력, 수정·삭제 알림, 전 영업일 확정분 취합 발송 | 일시중단 |

코드는 서버 패키지, API 경로, 프론트 폴더 이름에도 같이 써서 프로젝트끼리 경계가 겹치지 않게 한다.

## 3. 업무 영역 (축 A)

- 레일 항목은 원 사업계층별 분류체계의 업무 단위를 따른다. 가입 승인 등 업무 담당자가 처리할 일은 이 단위로 라우팅된다.
- 세부업무(예: 대출이동의 신규기관·보유기관, 계좌통합관리의 본인계좌일괄지급정지)는 업무 영역 아래 2단계다. 지금은 텍스트 필드, 코드화는 나중에 정한다.
- 조회 범위: 결제원 직원은 본인 업무의 전 기관, 운영·상황실·대외계는 전 업무·전 기관, 기관 담당자는 본인 업무의 결제원 담당자와 소속 기관 같은 업무 담당자만.

## 4. 보조 메뉴 (축 B) 2단계 출발점

| 메뉴 | 2단계 화면 | 주 사용자 |
| --- | --- | --- |
| 홈 | 지금 할 일 카드(정기 변경 진행률, 회신 대기 의견 요청, 다가오는 일시중단, 진행 중 테스트, 가입 승인 대기) | 전원, 그 사람에게 할 일이 있는 카드만 |
| 연락처 | 담당자 목록 · 담당자 상세(변경 이력) · 정기 변경 주간 등록과 진행 현황 | 전원, 정기 변경은 결제원 |
| 의견 요청 | 요청 목록 · 요청 작성 · 회신 현황·취합 / (기관) 내 회신함 · 회신 작성 | 결제원 작성, 기관 회신 |
| 기관 테스트 | 테스트 목록 · 테스트 상세(요구사항별 결과, 수행률) · 결과 등록 | 결제원 생성, 참가기관 등록 |
| 일시중단 | 진행 중·예정·지난 목록 · 등록 · 기관별 이력 | 결제원·기관 모두 등록 |
| 관리 | 가입 승인 · 알림 대상 설정 · 기관·업무 기준정보 | 결제원 권한자 |

"관리" 그룹은 메뉴 자리만 공통이 정하고 화면은 해당 기능 프로젝트가 만든다. 가입 승인과 기준정보만 공통 몫이다.

## 5. 공통이 기능 프로젝트에 제공하는 것

- Organization: 결제원(KFTC), 참가기관(Finance Organization), 이용기관(Use Organization), 기관 모노그램
- 업무 영역·세부업무 코드와 사용자별 조회·수정 범위 판정(서버 검증)
- 사용자·직무: 현업/전산(개발·운영·인프라·대외계·상황실), 내부망 접속 여부
- 알림: 알림 센터 + 메일·Mattermost 발송 인터페이스(데모는 앱 안 outbox)
- 첨부파일, 변경 이력(전·후 값), 엑셀 다운로드 공통 모듈
- 앱 셸과 디자인 토큰(레이어드 네이비), 목록 패턴(필터 칩 + 표 + 오른쪽 상세 패널)
- 홈 카드 슬롯: 기능 프로젝트가 자기 카드를 하나씩 끼운다

## 6. 확인 대기

1. "전체" 레일을 전 업무 담당 결제원 직원에게만 보일지.
2. 결제원 담당자의 연락처와 업무분장 관리를 공통 사용자 정보로 둘지, 연락처 기능에 넣을지. 초안은 공통(사용자)으로 두고 연락처가 조회한다.
3. 이용기관이 어느 기능을 쓰는지. CMS에만 해당하면 CMS 영역의 연락처·일시중단만 연다.
4. 기관 테스트를 이용기관에도 열지.
