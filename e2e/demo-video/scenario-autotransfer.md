# 2차 심사 발표 영상 장면표 — 자동이체 해지 결과 배치파일 개선

2차 심사(5분 발표)에 장표마다 넣을 **장별 무음 영상**을 이 폴더의 녹화 틀(`record.ts`·`compose.ts`·`helpers.ts`)로 찍기 위한 장면표다.
발표 전체 대본과 시간 배분은 `docs/presentation/scenario.md`(발표자료 PR)에 있고, 여기는 화면 동선만 적는다.
내레이션은 발표자가 직접 하므로 영상은 무음이다. **광고 느낌이 아니라 말 그대로 시연영상**으로 찍는다(SHY, 2026-11-21): 확대·말풍선 없이 실제 화면을 조작하는 커서만 보이고, 왼쪽 아래 알약으로 지금 누구로 로그인했는지만 표시한다. 카드는 대본(`docs/presentation/scenario.md`, 발표자료 PR 78)에 있는 세 장("회의를 마쳤습니다", "요건 확정", "며칠 뒤")만 둔다. 장면에서 짚을 곳은 `look()`(at-common.ts)으로 스크롤하고 커서를 잠깐 둔다.

장면 스크립트는 `scenes/at-prep.ts`, `at-biz.ts`, `at-dev.ts`, `at-ops.ts`, `at-susp.ts`이고 `DEMO_SCENARIO=autotransfer` 일 때 `scenes/index.ts` 가 이 장들을 고른다.

## 2. 녹화 전 데이터 준비

```bash
DEMO_SCENARIO=autotransfer e2e/demo-video/run.sh   # app.jar 를 새로 띄운 뒤 record.ts 앞에서 setup-autotransfer.ts 를 한 번 부른다
# → out/autotransfer.json (meetingRequestId, noticeId, surveyId, testPlanId, orgIds)
```

- 시드와 테스트 사이트(Render)는 바꾸지 않는다. 서버를 새로 띄울 때마다 다시 만든다(같은 서버에 두 번 돌리면 가입이 겹쳐 실패한다).
- 2026-11-21 새 서버에서 끝까지 돌려 확인했다: 의견조사 회신 3곳, 기관 테스트 수행률 10%(KB 40%, 테스트데이터 생성 완료 2/6).
- 기한·일정은 실행 날 기준 상대값이다(회의 회신 D+3, 의견조사 D+10, 테스트 수행 D0~D+14, 회의 일시 D+7 14:00).
- `DEMO_SCENARIO` 를 비우면 1차 영상처럼 시드만 쓴다. 장면 스크립트는 `out/autotransfer.json` 에서 id 를 읽는다.
- 데이터 준비는 KB국민은행 부담당 교체(백승호 → 남도윤, prep 의 변경 이력), 기관별 테스트 담당자, 자동이체 단체방 시행 안내 한 줄(ops)도 만든다.
- `run.sh` 는 녹화 뒤 `out/demo-{prep,biz,dev,ops,susp}.mp4` 를 장마다 뽑는다. 2026-11-22 녹화 길이: prep 18초, biz 56초, dev 40초, ops 18초, susp 32초.

## 4. 녹화 때 주의

- 회신 최종제출 버튼 이름은 "최종제출", 확인 시작 대화상자 버튼도 "확인 시작", 확정은 "조치 쓰고 확정" → "확정하기".
- 기관 테스트 화면은 창에 포커스가 돌아올 때 다시 읽는다(`switchSession` 뒤 결제원 화면에서 바뀐 수행률을 보이려면 페이지를 다시 연다).
- 운영 장은 우리 원 작업 지연이 아니라 **타 기관 수신 지연**으로 파일이 늦게 나가는 이야기다(SHY, 2026-11-22).
- 소통 채널은 3초마다 새 메시지를 읽으니 전송 뒤 3초 이상 기다린다. 자동이체 단체방은 시드상 방 id 2다.
- 열린 PR #75(첨부 반입 보안 검사)가 먼저 병합되면 공문 올리기 동선이 달라질 수 있다. 녹화 전에 main 을 다시 병합해 확인한다.
- 결제원 계정은 인터넷망에서 첨부를 올리고 내려받지 못한다. 결제원 장면은 내부망(망 전환 토글 기본값)으로 찍는다.
