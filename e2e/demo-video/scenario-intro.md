기준: 최종 산출물(main) + 최종 심사 기준(업무 관련성 30 · 확산 가능성 30 · 완성도 20 · 창의성·AI 활용 20) + 요청 사항(기능 연계 흐름, 구글폼식 분기, 약 198시간 × 94개 업무 = 연 18,612시간 절감, C-level 대상 장표, 로그인 주체 표시, 공지→회의 참석, 발송함, 장애 긴급 확인, 여러 업무를 고르는 일시중단 등록, 자막이 가리키는 곳만 비추는 강조, 장 제목을 크게, 마무리는 로고만).

## 2. 기능 연계 흐름(01)이 보여 주는 것

| 단계 | 화면에서 일어나는 일 | 전에는 → 이제는 |
| --- | --- | --- |
| ① 연락처 현행화 | 기관 담당자(김민준)가 로그인하자 6개월 지난 담당자 확인 창. "변동 없음" 한 번. 정기 변경 주간엔 "현행화 완료" 한 번. 바뀐 내역은 이력으로 남는다 | 결제원이 기관별 회신 메일을 열어 엑셀에 옮기던 것 → 기관이 직접 확인·현행화 |
| ② 최신 연락처로 의견 요청 | 결제원 담당자(홍성민)가 새 의견 요청의 대상을 고를 때 세부업무 칩 "내 계좌 한눈에"를 누르면 **방금 현행화된 명부**에서 그 세부업무 담당자들이 그대로 들어온다 | 수신자 목록을 메일함에서 긁어 모으던 것 → 연락처가 곧 수신자 명부 |
| ③ 분기 질문과 기관 회신 | 질문은 구글폼처럼 답에 따라 갈라진다(반영 가능 → 계획, 어려움 → 이유). 기관은 자기 답에 맞는 질문만 보고 웹에서 제출. 답을 바꾸면 다음 질문이 바뀌는 것을 두 번 보여 준다 | 첨부 회신서 양식 → 웹 폼, 해당 없는 질문은 보이지도 않음 |
| ③-2 공지에서 회의 참석 회신 | 기관 담당자가 공지·자료실의 회의 개최 안내를 보다가 글에 이어 둔 "회신하기"로 참석 여부와 참석자를 바로 답한다 | 공문 메일을 보고 참석 여부를 회신 메일로 따로 보내던 것 → 공지와 회신이 한 글에 |
| ④ 자동 집계·리마인드 | 질문별 답이 자동으로 모이고 건너뛴 질문도 표시. 미회신 기관에는 메일을 미리 보고 리마인드. 리마인드·알림 메일은 자동으로 나간다 | 회신서를 열어 취합표를 손으로 만들고 독촉 메일을 따로 쓰던 것 → 집계는 자동, 리마인드는 버튼 하나 |

## 3. 숫자 근거와 확인할 것

- **약 198시간 / 94개 업무 / 18,612시간**: 업무 1개 기준 연 약 198시간 절감(2026-10-28 수정, 이전 305시간), 사업 계층별 분류체계 소분류 94개 업무, 198×94=18,612. 문제 카드는 "업무 하나에서만, 해마다"를 크게 두고 "약 198시간", 설명 "메일을 하나하나 열고 이를 내부망에서 취합하는 데 걸리는 시간".
- **자동 테스트 590개** = 서버 433 + 화면 90 + E2E 67(2026-10-28 main 기준), **PR 60개**(#60). 카드에는 이 숫자만 두고 "코드 품질"·"12일" 문구는 뺐다(2026-10-29). app.jar 하나·외부 연결 없음은 영상에서 빼고 질의응답용으로 둔다.
- **제품명 표기**: 영상은 "연결이"로 통일한다.
- **발송함**: 시연 환경은 메일·매터모스트를 실제로 보내지 않고 발송함에 기록한다. 영상에서는 기관이 일시중단을 등록한 직후 발송함을 열어 "매터모스트" 알림 기록을 보여 준다(03). 실제 배포에서는 같은 자리에서 메일·매터모스트 채널로 나간다. 확정 취합의 발송 시각은 설정 `app.suspension.digest.cron`(기본 평일 16시)으로 바꾼다.
- **음성**: 이 환경에는 한국어 TTS가 없어 자막만 들어간다. 내레이션 대본(`narration.md`)을 녹음하거나 TTS로 만들어 파일을 주면 바로 입힌다(장면별 시각이 대본에 있다).
- **음악**: 외부 음원을 쓸 수 없어 합성 패드(임시)를 깐 판(`demo-bgm.mp4`)과 무음 판(`demo.mp4`)을 둘 다 만든다. 정식 음원이 있으면 바꿔 끼운다.
